# Verification and release policy

The I05 Lyons counterexample package has specific public-release authorization. That authorization does not extend to any other research result or to synchronizing private research material.

A proposed additional release must satisfy all of the following before the user is asked to approve the concrete package:

1. Independent status, semantics, and value audits identify the original question, check later work, establish the exact intended statement, and explain the substantive contribution. Failure to find a prior result is not proof that a problem remains open or that a result is new.
2. A complete proof or counterexample covers the declared statement. Fresh independent reviewers inspect a fixed version in read-only isolation; a complete result on a genuinely open main problem requires a second independent mathematical review. Essential computation has a rigorous, reproducible certificate and an independent check.
3. Writing is separate from verification. A fresh manuscript reviewer checks every theorem and proof, the mapping to verified mathematical material, the references, and an independent build. Compilation by itself does not establish correctness.
4. The proposed public package contains only the verified, approved scope and necessary reproducibility material. It contains no private candidates, unverified proofs, drafts, full source datasets, internal paths, or private research history.
5. The user explicitly authorizes that specific package. Any authorship, acknowledgments, disclosure, submission, or author-contact decision requires the user's separate direction.

All pull requests remain Draft unless the user gives new instructions. Do not merge, submit a manuscript, contact authors, decide authorship, publish research artifacts, or create automations under the framework authorization. There is no automatic synchronization from private research.

An internal verification verdict is not a public priority claim. A later authorized release should state its precise scope, verification coverage, known limitations, version, and release date without overstating novelty.
